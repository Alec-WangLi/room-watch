## 1. 产品共识

- 产品形态不变：**一台常开的 Windows 主机 + 本机 USB 摄像头**，事件驱动：
  有人进入 → 抓拍/录像 → 人脸识别 → 语音/推送。
- 优先级：**稳定性 > 性能 > 功能数量**。
  最在意的是「它必须一直活着，真出事时一定通知到我」。
- 性能与稳定性允许更换底层实现；但换引擎/编码器必须先用基准数据证明有收益。
- 推送投递层下一阶段重做：**持久化 outbox + 失败重试 + 多渠道 + 外部心跳**；
  现有渠道保留。
- 产品化是真实目标：开源下载者要能「装完即忘」，不需要理解会话/进程/命令行。
- Linux 智能家居主机是以后的事：**不要为 Linux 牺牲当前功能，也不要再加深 Windows 专属耦合**。
- 电脑需要保持登录（USB 摄像头不能在 Session 0 的 Windows 服务里采集）；
  安装器/向导注册登录时静默启动。

## 3. 本轮完成的内容

### M0 可观测性（0.1.11）

- `roomwatch/health.py`：健康快照、退出码、原子写、退出记录、停滞判定/看门狗。
- `roomwatch/diagnostics.py`：faulthandler + sys/threading excepthooks + atexit。
- `roomwatch/logutil.py`：日志轮转、`event=` 固定字段。
- `roomwatch/watcher.py`：每秒 `var/state/health.json`、`last_exit.json`、
  主循环停滞看门狗、退出码（0/2/3/4/5/6）。
- `guardian.py`：重启历史 `guardian_history.jsonl`、上次退出原因。
- `roomwatch/diag.py` + `rw diag`：脱敏诊断包（不收 `data/`）。

### M1 守护与自愈（0.1.12）

- `control.py`：`desired_state.json`（running/paused）、gallery PID 路径、
  `pid_matches`、`stop_gallery`。
- `gallery.py`：写 `var/state/gallery.pid`，只删自己的 PID。
- `guardian.py`：暂停语义、同时守护 watcher + gallery、单实例 owner lock、
  恢复/崩溃/暂停通知、自检失败通知、崩溃窗口退避、`--status` 扩展。
- `autostart.py`：计划任务优先（登录触发、失败重启、零闪窗），
  被安全策略拦截时回退 HKCU Run + VBS，并清理另一条旧入口。
- `selfcheck.py`：模型、目录、推送凭据、磁盘四项启动自检。
- CLI/GUI：`rw start` 后台启动并交给 guardian；`--foreground` 保留旧行为；
  `rw stop` 写 paused 并停 gallery + watcher；GUI 显示暂停/上次退出/自检摘要。
- 评审发现 2 个 Critical + 11 个 Important，全部修复并有 RED→GREEN 测试；
  全量测试（含集成测试）通过。

### 桌面版闪窗修复（beta）

- 原因：GUI 在检查更新等场景用 `subprocess.run` 启动 `python.exe`，
  没有 `CREATE_NO_WINDOW`，Windows 会闪一个控制台窗口。
- 修复：`roomwatch/gui.py` 新增 `_headless_flags()`、`_run_headless()`、
  `_update_check()`；检查更新、找解释器、预览/注册、重开界面、强杀兜底
  全部走隐藏控制台路径。
- 测试：`tests/test_gui_state.py` 新增 4 项；全量测试通过。
- 提交：`f6a0670 fix(gui): 子进程统一隐藏控制台窗口`。

## 5. 开发习惯与要求

- **分支**：`main` 稳定版；`beta` 测试版。新功能从 `beta` 切 `feat/<主题>`，
  完成后先合回 `beta`，稳定后再合回 `main`。不要直接改 `main`。
- **版本纪律**：前两位是所有者批准的基线，只许动第三位；不要替用户宣布正式版。
  当前 `main`/`beta` 都是 0.1.12；beta 多一个闪窗修复。下次发版建议先把 beta
  升到 0.1.13，再合回 main，避免同版本号内容不同。
- **不要擅自发 Release/tag**；发版需所有者明确同意。
- **测试**：新功能/修复先写失败测试；合并前跑全量 `rw test`（含集成测试）。
  测试必须离线，不依赖真实摄像头/网络。
- **凭据**：只放 `config.local.yaml`；不要打印、提交或会话里粘贴 token。
- **不绕过钩子**，不用 `--no-verify`，不 `git add -f` 隐私文件。
- **提交信息**用中文，带 `Co-Authored-By: Claude ...`。
- **引用**用语义锚点（函数/配置键/段名），不写会漂移的行号。
- **Windows 边界**：USB 摄像头只能在登录会话；不要把采集做成 Windows 服务；
  新代码不要把 Windows API 散落到核心逻辑（M6 会收口）。

## 9. 0.1.13 稳定性收口（同日续）

分支 `feat/0.1.13-stability`（从 `beta` 切出），`VERSION` 已升到 0.1.13。

- **闪屏根因**：打包后的界面没有 psutil，`procutil.pid_alive` 每 2 秒回退到
  `tasklist`，且兜底命令没有 `CREATE_NO_WINDOW`。现在界面打包自带 psutil
  （构建自检会拦截缺失），`procutil` / `updater` / `autostart` 的
  `tasklist`/`taskkill`/`schtasks` 兜底全部隐藏控制台，即使 psutil 丢失也不会闪。
- **相册端口**：首选端口被 Windows 保留（本机 8748–8847）或占用时，依次尝试
  8765 → 18765 → 28765 → 系统分配；实际地址写入 `var/state/gallery.json`，
  界面读取它打开浏览器，`rw diag` 也会收集该文件。
- **guardian 相册崩溃计数**：拉起成功不再清零计数；只有下一轮检查仍存活
  才算恢复。崩溃循环按退避重试，并在窗口内告警一次。
- **状态写入容错**：health / status / guardian_state / 退出记录写入失败不再
  中断主循环；原子写使用唯一临时文件名，并重试 Windows 瞬时占用。
- **测试**：新增闪屏兜底、端口回退、崩溃计数、并发原子写、崩溃转储失败的
  回归测试；全量 `rw test` 通过。
- **构建**：`dist/room-watch.exe` 自检通过（psutil 已打包）；已产出
  `dist/room-watch-0.1.13-setup.exe` 与 `.zip`。本机已覆盖安装 0.1.13
  （`config.local.yaml` 保留）；未推送、未发 Release。
- **安装器升级修复**：真机在旧监控进程运行时升级，Inno 弹「无法自动关闭所有
  应用程序」。现安装器在复制文件前先跑旧版 `rw stop`，再按安装目录路径强停
  残留进程（不碰用户自己的 Python）；`build-installer.ps1` 支持 `-OutputName`
  以便在安装器运行时换名构建。
- **首次配置向导**：真机升级时安装器无条件启动了 `rw setup`，用户以为配置丢了。
  现在只有 `config.local.yaml` 不存在（真正首次安装）时才启动向导。

待真机验证：界面打开期间是否彻底不闪；相册是否在 18765 可访问；
`guardian_history.jsonl` 里相册重启是否退避且只告警一次；
建议挂机 ≥24 小时观察 watcher 静默退出。
