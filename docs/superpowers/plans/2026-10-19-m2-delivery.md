# M2 投递层 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 把通知发送从「发出去就不管」改成持久化 outbox + 重试 + 多渠道扇出 + 外部心跳，保证断网、重启和部分渠道失效时不丢告警。

**Architecture:** 新增 SQLite `outbox` 表作为唯一发送入口；watcher 和 guardian 只负责入队，两个投递 worker（文字/图片、视频各一）从队列取任务并通过 `Notifier` 的渠道实现发送。guardian 另外按间隔请求用户配置的外部心跳 URL，整机失联时由外部服务提醒。

**Tech Stack:** Python 3.13/3.14 标准库 `sqlite3`/`threading`/`json`/`urllib`，现有 `requests`；SQLite WAL；unittest；Tkinter 设置界面。

**Spec:** `docs/superpowers/specs/2026-10-19-reliability-productization-design.md`（6.3 通知投递层）

## Global Constraints

- Windows 10/11 x64；USB 摄像头只能在登录会话采集；不要引入 Windows 服务。
- 只动修订号：本计划目标版本 `0.1.16`；未经所有者同意不发 tag / Release。
- 新功能先写失败测试；合并前跑全量 `rw test`（含集成测试）；所有新增测试必须离线，不依赖真实网络、摄像头或外部服务。
- 凭据只放 `config.local.yaml`；日志、测试输出、GUI 快照不得回显完整 webhook/token/心跳 URL。
- 主循环不得等待网络；发送失败不能影响监控继续运行。
- 通知优先级：文字 > 图片 > 视频；文字永不被视频挤出队列。
- 现有渠道（wecom_bot / wxpusher / serverchan）行为保留；旧配置 `notify.channel` 必须继续可用。
- 数据库迁移必须可重复执行；老事件库、老配置升级后不丢数据。
- **本计划不做按渠道的事件类型过滤**（Spec 6.3.2 的 event/digest 过滤）。本版所有启用渠道接收所有告警，critical 只影响排队优先级；过滤留到后续小版本，避免把投递可靠性版本扩成配置矩阵。

## Review Focus

- 断网 10 分钟后恢复：积压文字/图片应在 5 分钟内送达，且不重复。
- 进程在 `sending` 状态被杀：重启后该项必须重新投递，不能永远卡住。
- 同一事件重复入队（例如重试或重复调用）：`dedupe_key` 必须只留一条。
- 视频转码/上传很慢时：不得阻塞文字和图片；文字告警应优先发出。
- 所有渠道被禁用或心跳 URL 未配置：界面必须明确提示「告警不会送达 / 整机失联无法通知」，不能安静地失联。

**Files:**
- Create: `roomwatch/outbox.py`
- Test: `tests/test_outbox.py`

**Interfaces:**
- Consumes: 标准库 `sqlite3`, `json`, `datetime`, `pathlib`。
- Produces:
  - `STATUS_PENDING/SENDING/DELIVERED/FAILED/EXPIRED` 常量。
  - `@dataclass(frozen=True) OutboxItem(id, event_id, channel, kind, severity, payload, created_at, attempts, next_attempt_at, status, last_error, dedupe_key)`。
  - `@dataclass(frozen=True) DeliveryResult(ok: bool, retryable: bool = True, error: str = "")`。
  - `retry_delay(attempts: int) -> float`：`0→5s, 1→30s, 2→120s, 3→600s, 4→3600s, 5→21600s, ≥6→86400s`。
  - `class OutboxStore(db_path)`：`enqueue(...) -> int | None`、`enqueue_many(items) -> int`、`claim_next(now=None, lease_seconds=120, kinds=None) -> OutboxItem | None`、`mark_delivered(item_id, now=None)`、`mark_retry(item_id, error, retryable=True, now=None) -> str`、`recover_stale(now=None) -> int`、`expire_and_prune(media_dir, max_age_days=7, max_total_bytes=2GiB, now=None) -> dict`、`stats() -> dict`、`pending_count() -> int`、`last_success_at() -> str | None`、`record_channel_result(channel, ok, error="", now=None)`、`channel_health() -> dict[str, dict]`、`close()`。
  - 表结构字段与 Spec 6.3.1 一致；`dedupe_key TEXT UNIQUE`；`lease_until` 用于崩溃恢复；`outbox_meta` 表保存每个渠道最近成功/失败时间与错误。

- [ ] **Step 3: 实现 `roomwatch/outbox.py`**

关键实现要求：
- 连接：`sqlite3.connect(str(db_path), timeout=5)`；`PRAGMA journal_mode=WAL`；`PRAGMA busy_timeout=5000`。
- 时间统一 `datetime.now().isoformat(timespec="seconds")`；SQL 按 ISO 字符串比较。
- `claim_next` 先 `recover_stale`，再 `BEGIN IMMEDIATE`，按 `severity`（critical=0/event=1/digest=2）、`kind`（text=0/image=1/video=2）、`id` 排序；`kinds` 非空时只取指定 kind。
- `mark_retry`：`attempts+1`；不可重试 → `failed_permanent`；可重试 → `pending`，`next_attempt_at = now + retry_delay(attempts)`。
- `expire_and_prune`：过期 pending/failed → `expired`；删除 payload 中 `outbox_path` 指向的文件；`delivered` 超过保留期可删除行；容量超限时只淘汰 video/expired，不淘汰 text。
- `stats()` 返回 `pending/sending/delivered/failed/expired/oldest_pending_at/last_success_at`。
